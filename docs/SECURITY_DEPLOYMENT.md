# 学校本番運用のセキュリティ・配備チェックリスト

このアプリは運営者のサーバーやDBへ児童データを集めません。それでも、OAuth、共有ポリシー、配信オリジン、保存年限は学校側のデータ保護管理の対象です。

## 本番化の必須確認

- Google Drive API、OAuthブランド、`drive.file` と制限付きスコープ `drive.readonly` の審査状態を確認する。
- Google Cloudの［データアクセス］に登録するスコープを、`openid` / `userinfo.email` / `userinfo.profile` / `drive.file` / `drive.readonly` の5つに保つ。アプリが要求するのはこの5つだけで、これ以外が登録されていれば削除する。
- Workspace管理者がOAuthクライアントを信頼済みにし、児童→先生、先生→児童のユーザー指定Drive共有が校内ポリシーに合うことを確認する。
- `docs/config.js` の `allowedWorkspaceDomains` を学校のドメインに限定する。複数校運用は必要なドメインだけを列挙する。
- 可能な限り専用カスタムドメインを使い、`publicEntryUrl`、`allowedOrigins`、OAuthの承認済みJavaScript生成元を同じオリジンにする。
- `index.html` のCSPがGoogle Identity、Drive API、任意のGemini API以外の外部通信先を許可していないことをブラウザ開発者ツールで確認する。GitHub PagesではHTTPヘッダーを自由設定できないためメタCSPであり、`frame-ancestors` やHSTSが必要な場合はヘッダーを制御できる配信基盤を使う。
- Geminiを使う場合は、校内承認、保護者への説明、Google CloudのAPIキー制限、保持／学習利用条件を確認する。使わない学校はAPIキーを設定しない。

## 運用

- 招待URLは学習支援ツールなど必要な参加者にだけ配る。漏えい時は直ちに再発行する。
- 学期末、学年末、担任交代前に先生所有Driveへ完全バックアップを作成し、学校の保存年限と削除ルールに従う。
- 安全性チェックで除外された共有ファイルは、Drive所有者とJSON内メールの不一致、失効招待、異なるクラスIDを確認する。原ファイルは自動削除しない。
- 競合メッセージが出たら、画面を最新に更新し、内容を確認してから再入力する。

## 受入れ試験

1. 署名付き招待で参加でき、改ざん、期限切れ、再発行前のURLが新規参加に使えない。
2. 個人アカウン2つと学校ドメインの先生／児童で、参加・提出・画像・承認・返却を確認する。
3. 別端末で同じポートフォリオを更新し、古い画面の保存が競合として拒否される。
4. 完全バックアップフォルダにmanifest、class、portfolio、channel、共有画像の複製が作成される。
5. 許可外ドメイン、許可外オリジン、Workspace共有禁止で利用者向けエラーが表示される。
