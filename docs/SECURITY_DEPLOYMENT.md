# 学校本番運用のセキュリティ・配備チェックリスト

このアプリは、先生ご自身がコピーしたスプレッドシートに束ねられた Google Apps Script として、
先生ご自身のアカウントで動きます。運営者のサーバーや DB へ児童データを集めません。
それでも、権限・公開範囲・保存年限は学校側のデータ保護管理の対象です。

退役した Drive ネイティブ版（2026-08-23 まで）の配備手順は
[legacy/drive-native/OAUTH_SHARED_RECORDS_SETUP.md](../legacy/drive-native/OAUTH_SHARED_RECORDS_SETUP.md)
にあります。**現在の運用には使いません。**

## 公開する先生が確認すること

- **「はじめの設定」を、児童に URL を配る前に押す。** 押すまでは誰の画面にも「まだ準備中です」としか出ません。
  ウェブアプリからは誰も先生になれない形なので、児童が先に開いてもその子が先生になることはありません。
- デプロイは **実行するユーザー: 自分 ／ アクセスできるユーザー: 同じ組織内の全員**。
  - **「全員（匿名ユーザーを含む）」を選ばない。** 誰が書いたかを確かめられなくなります。
    その状態では、アプリは画面を出さずに止めます。
- **スプレッドシートを児童に共有しない。** 児童が持つのはウェブアプリの URL だけで、
  シートの権限は一切ありません。共有すると、その前提が崩れます。
- `appsscript.json` の `oauthScopes` が 4 本のままであることを確認する
  （`spreadsheets.currentonly` / `script.container.ui` / `script.external_request` / `userinfo.email`）。
  **`auth/drive` など、ドライブ全体のスコープを足さない。**
  マニフェストを置かずに Apps Script へ貼ると、GAS がスコープを推測して広げます。
- 参加は既定で承認制のままにする。URL を知っているだけで名簿に入れる状態にしない。
- Gemini を使う場合は、校内承認、保護者への説明、Google Cloud の API キー制限、
  保持／学習利用条件を確認する。使わない学校は API キーを設定しない。
  無料ティアのキーでは、送信した内容が Google のモデル改善に使われる場合があります。

## 情報担当・管理者が確認すること

- Workspace で Apps Script のウェブアプリ公開が許可されているか。
- 「外部ファイルのコピー」が許可されているか（禁止されているとコピーで配れません。
  その場合は貼り付け手順を案内してください）。
- フィルタリングで `accounts.google.com` / `script.google.com` / `googleusercontent.com` /
  `docs.google.com` が通ること。Gemini を使う場合は `generativelanguage.googleapis.com` も。
- 画面の部品は外部から読み込みません（フォントを除く。届かなくても字の形が変わるだけです）。

## 運用

- クラスの URL は、学習支援ツールなど必要な参加者にだけ配る。
- **1 ファイル = 1 クラス。** 学年やクラスが変わるときは、新しいコピーを作る。
- 学期末・学年末・担任交代前に、スプレッドシートを複製して控えを取り、
  学校の保存年限と削除ルールに従う。運営者の中央バックアップはありません。
- シートを直に触った後は、メニュー［ふりかえりジャーナル］＞［シートを点検する］を実行する。
  見出しの名前を変えた・列を消した場合だけ、そこの読み書きが止まります。
- **配り終えたコピーは、その時点のコードで動きます。** 直しは自動では届きません。
  記録が壊れる直しを届けるときだけ、貼り直しをお願いしてください
  （[docs/copy-distribution.md](copy-distribution.md) §6）。

## 受入れ試験

CI では Google Workspace の組織ポリシーを再現できません。実機で次を確認してください。

1. **別のアカウント**（できれば学校のアカウント）でコピーリンクを開き、コピーが作れる。
2. コピーしたファイルにメニュー［ふりかえりジャーナル］が出て、［はじめの設定］で
   6 枚のシートができ、「_meta」に自分のアドレスが入る。
3. デプロイした URL を先生が開くと先生の画面、児童が開くと参加申請の画面になる。
4. 承認するまで児童は本体に入れない。承認後に提出でき、
   **コピーしたそのファイル**の「ジャーナルデータ」に行が増える。
5. 児童の画面に、ほかの児童のメールアドレスが出ない。
6. 児童のブラウザのコンソールから `google.script.run.opResetData()` を呼んでも
   `FORBIDDEN` で止まる（画面の出し分けではなくサーバー側で止めていることの確認）。
7. 「ジャーナルデータ」の列を 1 本入れ替えても、提出が正しい列に入る。
   ［シートを点検する］が並びの違いを「直さなくてよい」と言う。
8. 「状態」の列を消して［直せる範囲で直す］を押すと、右端に足され、既存の行が `active` になる。
   見出しの名前を変えた場合は**直さず**、どこが違うかを名指しする。
