# 📔 ふりかえりジャーナル

小学校の児童が日々の学びを記録し、先生が閲覧・返却・分析できるWebアプリです。

本番入口は [共通URL](https://reflection-journal.giga-school.com/) です。先生・児童とも、このURLまたは先生が発行した招待URLを開くだけで利用できます。学校ごとの配布・デプロイ・スプレッドシート作成はありません。

## 結論：現在版はGASを使いません

現在の本番版は、GitHub Pagesが配信する静的なHTML／CSS／JavaScriptからGoogle Identity Servicesでログインし、ブラウザがGoogle Drive REST APIへ直接通信します。

- 本番でGoogle Apps Script（GAS）は実行しません。
- Firebase／Firestore、運営者所有のサーバー、中央データベースも使いません。
- Google Driveを、利用者自身が所有するデータ保存先として使います。
- 運営者のGoogleアカウントを経由して提出・返却を書き込むことはありません。
- 通常の記録通信は「ブラウザ ↔ Google Drive」です。任意のGemini支援を先生が実行した時だけ、対象本文をブラウザからGoogle Generative Language APIへ送ります。

リポジトリのルート直下には、移行前の `.gs` やGAS用HTMLが履歴資料として残っています。これらはGitHub Pagesの本番入口 `docs/index.html` から読み込まれず、現在版の運用・デプロイには使用しません。

## できること

### 先生

- 複数クラスの作成・切替と、最後に開いたクラスへの復帰
- 署名付き・期限付きの専用URL、QRコード、招待文の発行・失効・再発行
- 児童画面の事前確認、参加申請の承認／除外、1人／一括の事前名簿登録
- 当日テーマと曜日別テーマの配信
- 提出率、検索、未返却／返却済みの絞り込み、本文・画像の確認
- クイックスタンプ、返却取り消し、本文範囲へのコメント、全体コメント、一括返却
- Geminiによる単件／一括コメント下書きと範囲提案（任意・先生の確認必須）
- 今日の提出数、記述量／気持ちの変化検知、14日間の気持ちヒートマップ
- CSV出力、印刷／PDF保存、先生のDriveへのクラス完全バックアップ

### 児童

- QRコードまたは専用URLからのクラス参加
- 画面サイズに応じて書く領域を優先するノート画面と［広く書く］表示
- 開いている画面内の未提出下書き、YWT／KPT／5W1Hなどの型、書き出し、カテゴリ別ヒント
- テーマ、本文、気持ち、画像の提出と完了演出
- カレンダー、過去の記録、新着返却、全体／本文範囲のおへんじの閲覧
- 1か月以上前の自分の文章へのメッセージ
- 児童向け固定UIのふりがな、端末／ブラウザの戻る操作によるアプリ内移動
- PWAインストールと、入力を中断しない更新通知

ふりがなはアプリが用意した児童向け固定文言に付きます。先生が入力したテーマやおへんじ、児童自身が入力した文章へ自動でふりがなを生成する機能ではありません。

## データの流れ

```text
GitHub Pages（画面を配信）
        │ Googleログイン
        ▼
児童のGoogle Drive                    先生のGoogle Drive
├─ ポートフォリオJSON ──閲覧共有──▶ 先生
├─ 添付画像           ──閲覧共有──▶ 先生
│
児童 ◀──閲覧共有── 児童別チャンネルJSON ─┤
                         └─ クラス設定JSON（非共有）
```

1. 先生がクラスを作ると、先生のDriveにクラス設定が作成されます。
2. 児童が招待URLから参加すると、児童のDriveにポートフォリオが作成され、先生へ閲覧者として共有されます。
3. 先生が承認すると、先生のDriveに児童別チャンネルが作成され、その児童へ閲覧者として共有されます。
4. 児童は自分のポートフォリオだけを更新し、先生は自分のチャンネルだけを更新します。
5. 先生は共有された提出を読み、児童は共有されたテーマ・承認状態・おへんじを読みます。

提出と返却を別の所有者・別のファイルに分けるため、先生が児童の原文を変更したり、児童が先生のおへんじを変更したりしません。

## 何がどこに保存されるか

| データ | 所有者 | 共有先 | 主な内容 |
| --- | --- | --- | --- |
| クラス設定JSON | 先生 | 共有しない | クラス名、クラスコード、名簿、参加状態、テーマ、任意のGemini APIキー |
| 児童ポートフォリオJSON | 児童 | 先生を閲覧者にする | 本文、気持ち、添付画像ID、過去の自分へのメッセージ |
| 添付画像 | 児童 | 先生を閲覧者にする | 最大辺1600px・JPEGへ変換した作品／写真 |
| 児童別チャンネルJSON | 先生 | 対象児童を閲覧者にする | テーマ、承認状態、おへんじ、スタンプ、本文範囲コメント |
| 未提出下書き | ブラウザメモリ | 共有しない | 入力途中のテーマ、本文、気持ち。再読込みや終了で消去 |
| 既読状態・前回の役割／クラス | 利用端末 | 共有しない | 画面復帰と新着表示に必要な最小情報 |

Drive上のJSONと画像は通常のDriveファイルとして所有者のアカウントに作成されます。運営者の中央バックアップはありませんが、先生はクラス設定からクラス設定・検証済みポートフォリオ・おへんじ・共有画像の複製を自分のDriveへ作成できます。

## Google権限とログイン状態

最初のGoogle認可では、ログイン情報と `drive.file` だけを要求します。その後、先生または児童の画面を開く時に、相手から共有された記録を同期するための `drive.readonly` を利用者に説明し、追加要求します。

| スコープ | 用途 |
| --- | --- |
| `drive.file` | このアプリがその利用者のDriveに作成した専用ファイルの作成・更新・共有 |
| `drive.readonly` | 相手のアカウントから共有された提出、テーマ、おへんじ、画像の検索・読込み |

`drive.readonly` を過去に認可済みならGoogleの追加同意画面は省略される場合があります。許可しない場合、自分所有ファイルの作成はできても、先生と児童の共有記録は同期できません。

`drive.readonly` はDrive全体の閲覧を許可する広い制限付きスコープです。実装は `sharedWithMe` とアプリ固有の `appProperties`（`rjType`、`rjClassId` など）で対象を絞り、アプリ専用の共有ファイルだけを表示します。一方、書込みは `drive.file` の範囲に限定します。

- 既定ではアクセストークンをJavaScriptメモリにだけ保持し、`sessionStorage`、`localStorage`、Cookieへ残しません。共有GitHub Pagesオリジン上の他アプリとの境界を強化するためです。
- ページ再読込みやPWA更新後は再ログインが必要です。Googleで認可済みなら、通常はパスワード再入力なしで進みます。
- 前回の役割を復元し、先生の場合は最後に開いたクラスも開きます。児童の場合は参加済みクラス一覧へ戻ります。どちらもクラスが1つだけなら、一覧を経由せずそのクラスを開きます（戻る操作で一覧へ戻れます）。
- タブ／PWAを終了した場合もトークンは残りません。
- `localStorage` にはトークンや児童本文を保存せず、既読状態、前回の役割・クラスIDだけを保存します。旧版が保存した下書きも起動時に削除します。

詳しい権限境界は [Driveネイティブ設計](docs/DRIVE_NATIVE_ARCHITECTURE.md)、運営者の設定は [OAuth設定手順](docs/OAUTH_SHARED_RECORDS_SETUP.md) を参照してください。

## 招待URLの性質

- 招待情報は先生のブラウザがECDSA P-256で署名し、URLの `#join=...` 部分へ格納します。新規参加時に署名、有効期限、発行世代を検証します。
- URLフラグメントはGitHub PagesへのHTTPリクエストには送信されません。
- 中央レジストリがないため、クラスコードだけでクラスを検索・参加することはできません。専用URLまたはQRコードを使います。
- 既定の招待有効期限は35日です。先生は「招待URLを失効・再発行」で旧URLを新規参加に使えなくできます。
- 招待URLを受け取った人は参加申請画面を開けるため、公開Webページなどへ無制限に掲載しないでください。

## 制約と、できないこと

- 学校のWorkspaceポリシーが児童→先生または先生→児童のDrive共有を禁止している場合、アプリは制限を回避できません。その組み合わせでは管理者による共有許可が必要です。
- 学校が外部アプリや制限付きスコープを禁止している場合、Workspace管理者が共通OAuthクライアントIDとスコープを許可する必要があります。
- 中央アカウント管理、中央クラス検索、運営者による提出内容の閲覧、運営者所有の中央バックアップはありません。
- PWAは画面資産をキャッシュしますが、Googleログイン、Drive同期、提出・返却はオフラインでは動きません。
- 複数端末の未提出下書きと既読状態は同期しません。提出済みデータはDriveから各端末へ読み込まれます。
- 心のバイタルの変化検知は診断ではありません。必ず対面の様子と合わせて使います。
- Gemini支援は任意です。児童本文の外部送信について学校の承認を得たことを画面で明示した場合だけ利用でき、生成内容は先生が確認してから返却します。

## 運営者の初期設定

先生や児童のデプロイ作業はありません。アプリ運営者だけが共通設定を一度行います。

1. Google Cloudでプロジェクトを作成し、Google Drive APIを有効化します。
2. Google Auth Platformのブランド、対象ユーザー、データアクセスを設定します。
3. `drive.file` と `drive.readonly` を追加します。
4. 外部ユーザーへ公開する場合は、ブランド確認と制限付きスコープのOAuth審査を完了します。Googleの判定によりセキュリティ評価が必要になる場合があります。
5. OAuthクライアントを「ウェブアプリケーション」で作成します。
6. 承認済みJavaScript生成元へ `https://reflection-journal.giga-school.com` を登録します。
   ここが実際のオリジンと1文字でも違うと、アプリは開けるのにログインだけができません。
7. `docs/config.js` の `googleClientId`、`publicEntryUrl`、`allowedOrigins`、必要に応じて `allowedWorkspaceDomains` を設定します。クライアントIDはブラウザ用の公開識別子であり、クライアントシークレットは配置しません。複数アプリが同居するGitHub Pagesオリジンより、学校利用では専用カスタムドメインを推奨します。
8. GitHub Pagesの公開元を `main` ブランチの `/docs` にします。

学校ごとのGAS配布やデプロイは不要です。学校アカウントについては、各校のWorkspace管理者が組織ポリシーに沿って同じ共通OAuthクライアントを許可します。

## 本番ソースと旧GAS資産

本番仕様を確認する時は、次のファイルを正とします。

| ファイル | 役割 |
| --- | --- |
| `docs/index.html` | GitHub Pagesの本番入口 |
| `docs/drive-app.js` | Google認可、先生・児童の画面と操作 |
| `docs/drive-core.js` | データモデル、招待、分析、CSV |
| `docs/drive-api.js` | Google Drive REST API通信 |
| `docs/kit/` | 他アプリへ持ち出せる共通部分（ID・署名付き招待・Drive通信・共有記録の検証・ログイン方針） |
| `docs/drive.css` | レスポンシブUIとアクセシビリティ |
| `docs/config.js` | 共通URLとOAuthクライアントID |
| `docs/sw.js` | PWAの画面資産キャッシュと更新 |

`docs/kit/` はこのアプリに依存しません。GASでマルチテナント化している別のアプリを同じ「Driveネイティブ・分散ポートフォリオ」方式へ移すときは、`docs/kit/` をコピーし、記録の形と画面だけを書きます。手順は [GAS版からの移し替え手順](docs/PORTING_FROM_GAS.md)、キットの詳細は [キットのREADME](docs/kit/README.md) にあります。

ルート直下の `*.gs`、`index.html`、`app.html`、`qr.html` などは移行前のGAS版です。検索結果に現れても、本番版の動作根拠にはしません。また、現在版を使うためにApps Scriptへ貼り付けたりデプロイしたりする必要はありません。

## 公開前の実アカウント確認

CIではGoogle Workspaceの組織ポリシーを再現できません。個人アカウント2つと、同一学校ドメインの先生・児童アカウントで、次を確認してください。

1. 先生がクラスを作成し、専用URLを発行する。
2. 児童が参加し、先生が承認する。
3. 児童が本文と画像を提出し、先生側へ表示される。
4. 先生が本文・画像を閲覧し、おへんじを返却する。
5. 児童側へテーマと返却内容が表示される。
6. 再読込み後は再ログインが求められ、ブラウザの保存領域にアクセストークンが残らない。
7. 共有が組織ポリシーで拒否された時、利用者向けエラーと再共有操作が表示される。

特に、別ユーザーが作成して共有した専用ファイルを `drive.readonly` + `sharedWithMe` で取得できること、書込みがアプリ作成ファイルに限られることを確認します。
