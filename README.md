# 📔 ふりかえりジャーナル (Reflection Journal)

**「ふりかえりジャーナル」**は、毎日の5分間で児童のメタ認知を育み、先生との深い信頼関係を築くための次世代教育Webアプリケーションです。

従来の「紙のノート」や「単なるデジタルフォーム」を超え、児童の「心のバイタルサイン」を可視化し、AIが先生のフィードバックを支援することで、学校を**「データに基づき、一人ひとりの心に寄り添う場所」**へとアップデートします。

## ✨ コンセプト：単なる日記から「革命的なインフラ」へ

*   **心のバイタルサイン（エモーショナル・ウェザーマップ）**: 毎日の記述から児童の感情の変化を14日間のヒートマップとして可視化。小さなSOSを「起きる前に」察知します。
    
*   **先生と子供の交換日記**: 評価や採点ではなく、「対話」を目的としたUI設計。先生からの温かいおへんじ（通知）が児童の心に直接届きます。
    
*   **究極のZero-Config（環境構築不要）**: `Node.js`や`npm`は一切不要。3つのファイル（`code.gs`・`Tenant.gs`・`index.html`）をGoogle Apps Scriptにコピペするだけで、スプレッドシートやフォルダが自動で全構築されます。
    
*   **マルチテナント対応（共通URLで配布可能）**: 「アクセスユーザーとして実行」構成により、1つのURLを配るだけで、ユーザーごとに独立したデータベースが本人のGoogle Driveに作られます。GitHub Pages のPWAシェルからアプリとしてインストールも可能。
    

## 🚀 主な機能

### 🎒 児童向け機能（Student UI）

*   **魔法のヒント＆テンプレート**: 「何を書けばいいかわからない」をゼロにする、タップで入力できるヒント辞書（YWT、KPTなど）。
    
*   **過去の自分との対話**: 1ヶ月前の自分のジャーナルがランダムで表示され、今の自分からメッセージを送るリフレクション機能。
    
*   **完全なルビ（ふりがな）対応**: すべてのボタンや文章に美しいルビを完備。低学年でも一人で操作可能。
    
*   **おへんじ通知＆達成感の演出**: 先生からおへんじが届くとポップアップでお知らせ。提出時には画面いっぱいに紙吹雪が舞います。
    
*   **安心の自動保存**: 入力途中に誤って画面を閉じても、入力内容はブラウザに自動で保存されます。
    

### 👩‍🏫 教員向け機能（Teacher UI）

*   **ダッシュボード＆心のバイタル**: 今日の提出率（ドーナツチャート）や、クラスの感情の波（ヒートマップ）を一目で把握。
    
*   **AI要注目アラート**: 「ネガティブな感情が続いている」「急激に文字数が減った」児童をAIが自動ピックアップ。
    
*   **直感的な名簿エディタ**: アプリ画面上から直接、児童の追加・編集・削除が可能。
    
*   **Gemini AI フィードバック支援**: 未返却のジャーナルに対して、ハイライト（文章の抽出）と温かいコメント案をワンクリックで一括生成。
    
*   **一括エクスポート**: 学期末の記録用に、指定した期間・児童のデータを美しいPDFやCSVとして出力可能。
    

## 🏗️ アーキテクチャ（マルチテナント3層構成）

本アプリは「**1つの共通URLに、各ユーザーがログインするだけで、それぞれ自分のデータベースに接続される**」マルチテナント構成になっています。

```
┌─────────────────────────────────────────────┐
│ ① 配布層: GitHub Pages (docs/ = PWAシェル)   │  共通URL・ホーム画面に追加できる
│    https://gigayama.github.io/Reflection_Journal/ │
└──────────────┬──────────────────────────────┘
               │ 全画面 iframe 埋め込み
┌──────────────▼──────────────────────────────┐
│ ② アプリ層: GAS スタンドアロン Webアプリ      │  「アクセスユーザーとして実行」
│    code.gs / Tenant.gs / index.html          │
└──────────────┬──────────────────────────────┘
               │ UserProperties でユーザーごとに自動分離
┌──────────────▼──────────────────────────────┐
│ ③ データ層: ユーザーごとのスプレッドシート     │  本人の Drive・本人所有
│    児童名簿 / ジャーナルデータ / テーマ設定    │
└─────────────────────────────────────────────┘
```

*   **UserProperties による分離**: 「次のユーザーとして実行: アクセスしているユーザー」でデプロイすると、API実行・Driveアクセス・プロパティ保存がすべて「ログイン中の本人」の権限で行われます。DBのIDやAPIキーなど個人の設定は `UserProperties` に保存されるため、アカウントごとに完全に分離されます。
*   **先生と児童の関係**: 先生がオンボーディングで「新しくデータベースを作成」→ 作成されたスプレッドシートを児童に**編集者として共有** → 児童は同じ共通URLを開き「既存のスプレッドシートを紐付け」にそのURLを貼るだけで参加できます。
*   **後方互換**: 旧来のバインド型/「自分として実行」デプロイでも従来どおり動作します（`getSs_()` と `tGetProp_()` が ScriptProperties へフォールバックします）。

## 🛠️ 導入方法

プログラミングの知識は一切不要です。以下の手順に従って設定してください。

### 1. GAS プロジェクトの作成（スタンドアロン）

1.  [script.google.com](https://script.google.com) で「新しいプロジェクト」を作成（スプレッドシートには**バインドしない**）。
    
2.  プロジェクト名を「ふりかえりジャーナル」等に変更します。
    

### 2. コードの配置

1.  最初からある `コード.gs` の中身をすべて消し、本リポジトリの `code.gs` を貼り付けます。
    
2.  ファイル追加（＋）で「スクリプト」を選び `Tenant` という名前にし、本リポジトリの `Tenant.gs` を貼り付けます。
    
3.  ファイル追加（＋）で「HTML」を選び `index` という名前にし、本リポジトリの `index.html` を貼り付けます。
    
4.  プロジェクトの設定（⚙️）で「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、本リポジトリの `appsscript.json` の内容で置き換えます。
    
5.  💾 保存ボタンを押します。
    

### 3. アプリの公開（デプロイ）⚠️ 設定が重要

1.  画面右上の「デプロイ」>「新しいデプロイ」>「ウェブアプリ」を選択。
    
2.  **必ず**以下の設定でデプロイします：
    
    *   次のユーザーとして実行：**ウェブアプリケーションにアクセスしているユーザー**
        
    *   アクセスできるユーザー：**全員（Googleアカウント）**（※学校ドメイン内に限定する場合は同一ドメイン）
        
3.  表示された **exec URL**（`https://script.google.com/macros/s/…/exec`）を控えます。
    
4.  各ユーザーの初回アクセス時に「アクセスを承認」画面が出ます（本人の権限でDBやDriveにアクセスするためです）。
    

### 4. GitHub Pages（PWAシェル）の公開 — 任意

1.  このリポジトリをフォークし、`docs/config.js` の `appUrl` に手順3の exec URL を記入します。
    
2.  リポジトリの Settings > Pages で「Deploy from a branch」/ ブランチ `main` / フォルダ `/docs` を選択。
    
3.  公開された共通URL（例: `https://gigayama.github.io/Reflection_Journal/`）を配布します。スマホでは「ホーム画面に追加」でアプリとしてインストールできます。
    
4.  `appUrl` を空のままにした場合は、初回アクセス時に画面上で exec URL を入力してもらう方式になります（端末の `localStorage` に保存）。
    

### 📲 アプリとしてインストール（PWA）

シェルURLを開くと、端末に「アプリ」としてインストールできます。インストール後はホーム画面のアイコンから全画面（スタンドアロン）で起動します。

*   **Chrome / Edge（Android・PC）**: 画面下部に表示される「インストール」バーをタップするか、ブラウザのメニュー（︙）から「アプリをインストール」を選択。
    
*   **Safari（iPhone / iPad）**: 共有ボタン（□↑）→「**ホーム画面に追加**」をタップ（画面下部に手順の案内バーが表示されます）。
    
*   **Safari（Mac）**: メニューバーの「ファイル」→「Dockに追加」。
    

### 5. 使い始める（オンボーディング）

*   **先生**: 共通URLを開く → 「🎒 新しくはじめる」→ 自分の Drive に DB スプレッドシートが自動作成されます。作成された DB を児童のアカウントに**編集者として共有**し、その URL を児童に配ります。
    
*   **児童**: 共通URLを開く → 「🔗 既存のスプレッドシートを紐付け」に先生から配られた URL を貼り付けるだけ。あとは先生が名簿に児童を登録すれば完了です。
    

### 6. APIキーの設定（AI機能を利用する場合）

先生がアプリの設定画面から Gemini API キーを保存します。キーは**その先生の `UserProperties`** に保存され、他の利用者と共有されることはありません。

### 7. DBテンプレートの配布（配布元向け・任意）

「新しくはじめる」で空シートから構築する代わりに、雛形スプレッドシートを複製させることができます。

1.  雛形となるスプレッドシート（`児童名簿`・`ジャーナルデータ`・`テーマ設定` シート入り）を用意し、**「リンクを知っている全員が閲覧可」**で共有します。
    
2.  GAS プロジェクトの「スクリプト プロパティ」に `sp_dbTemplateId` = 雛形のファイルID を設定します。
    
3.  以後、「新しくはじめる」を押したユーザーの Drive に雛形の複製（本人所有）が作られます。
    

> **💡 Zero-Config について:** DBの作成・必須シートの構築・画像保存用フォルダの作成は、すべて初回利用時に自動で行われます。ユーザーが手作業でスプレッドシートを準備する必要はありません。

## 🔒 セキュリティと設計上の注意

*   **iframe 埋め込み（`ALLOWALL`）について**: GitHub Pages のシェルから埋め込むため、GAS 側は `XFrameOptionsMode.ALLOWALL` を設定しています。GAS は埋め込み元オリジンを限定できないため、理論上は任意のサイトが本アプリを iframe 埋め込みできます（クリックジャッキング等のリスク）。本アプリは Google ログイン必須・データは本人の Drive のみ・書き込みは `google.script.run` 経由という構成でリスクを緩和していますが、この特性は理解した上で運用してください。
    
*   **個人設定は必ず `UserProperties`**: APIキー・DB ID・画像フォルダ・週間テーマなど個人ごとに変わる設定はすべて `UserProperties`（`tSetProp_`）に保存されます。`ScriptProperties` に置いてよいのは `sp_dbTemplateId` のような配布元の共有設定のみです。
    
*   **OAuth スコープ**: `appsscript.json` で明示管理しています。テンプレート複製（`DriveApp.makeCopy`）・画像/エクスポートフォルダ・PDF出力（`DocumentApp`）のため `drive` / `documents` スコープが必要です。これらの機能を使わない場合は `drive` を `drive.file` に縮小できます。
    
*   **Service Worker のキャッシュ範囲**: PWA シェルはシェル資産（HTML/JS/manifest/アイコン）のみをキャッシュし、GAS 側（認証・データ）は**一切キャッシュしません**。
