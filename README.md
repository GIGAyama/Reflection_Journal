# 📔 ふりかえりジャーナル (Reflection Journal)

**「ふりかえりジャーナル」**は、毎日の5分間で児童のメタ認知を育み、先生との深い信頼関係を築くための次世代教育Webアプリケーションです。

従来の「紙のノート」や「単なるデジタルフォーム」を超え、児童の「心のバイタルサイン」を可視化し、AIが先生のフィードバックを支援することで、学校を**「データに基づき、一人ひとりの心に寄り添う場所」**へとアップデートします。

> 📖 **画面ごとの操作手順は [MANUAL.md](MANUAL.md)（操作マニュアル）にまとめています。**
> このREADMEは「何ができるアプリか」「どう作られているか」「どう設置するか」を説明します。

## 🧭 3行でわかるアプリの中身

1. 児童は毎日、今日のテーマについて数行のふりかえりを書いて提出します（下書きは自動保存、書き出しヒント・テンプレートつき）。
2. 先生は提出を一覧で受け取り、スタンプ1タップ / コメント / 本文へのマーカー（ハイライト）で「おへんじ」を返します。Gemini AI にコメント案を一括で下書きさせることもできます。
3. 溜まった記録は、提出率のドーナツ・過去14日の感情ヒートマップ・気になる児童の自動検知として先生に返り、CSV / 印刷帳票で書き出せます。

| 立場 | やること | 必要なもの |
| --- | --- | --- |
| 運営者（アプリアカウントの持ち主） | 最初に1回だけ設置する（下記「🛠️ セットアップ手順」） | Googleアカウント・GAS・GitHub Pages |
| 先生 | 共通URLを開く → クラスを作る → 児童用URLを配る → おへんじを返す | Googleアカウントだけ |
| 児童 | 配られたURL（またはQR）を開く → Googleサインイン → 書いて提出する | Googleアカウントだけ |

## ✨ コンセプト

*   **心のバイタルサイン（エモーショナル・ウェザーマップ）**: 毎日の「気持ち」の選択と記述量から、児童の状態を14日間のヒートマップとして可視化。小さなSOSを「起きる前に」察知します。
*   **先生と子供の交換日記**: 評価や採点ではなく、「対話」を目的としたUI設計。先生からの温かいおへんじが、児童の画面に通知として直接届きます。
*   **真のマルチテナント**: 1本のGASと共通URL1つで、**先生（クラス）ごとに独立したスプレッドシートDBを自動生成**。データは先生自身が所有し、**児童はシートへの権限を一切持ちません**。
*   **クラスコード方式**: 先生がクラスを作ると「児童用URL（`?t=クラスコード`）」が発行されます。児童はURLを開いてGoogleサインインするだけ。共有設定もIDのコピペも一切不要です。

## 🚀 主な機能

### 🎒 児童向け機能（Student UI）

児童の画面は**1画面完結**です。左に月別カレンダー、中央にノート（今日のテーマ＋本文）、右にサポートツール・気持ち・画像・提出ボタンが並びます（スマホ縦持ちではノートが最上部に来ます）。

| 機能 | 具体的にできること |
| --- | --- |
| 今日のテーマ | 先生が設定したテーマが自動表示されます。未設定の日は曜日別テーマ、それも無ければ「今日の学びをふり返ろう」が出ます |
| 魔法のヒント | 「気持ち」「学び」「つながり」「次へ」の4カテゴリ × 3つ、計12個の書き出し文をタップでカーソル位置に挿入 |
| テンプレート | **YWT法 / KPT法 / 5W1H / 3つのきづき** の4種類の型を1タップで挿入 |
| ランダムな書き出し | 4種類の書き出し文からランダムで1つ挿入 |
| 気持ちをえらぶ | 😊うれしい / 😠くやしい / 💡なるほど / 🤔もやもや の4択（ヒートマップの色になります） |
| 画像をのせる | 写真を1枚添付。ブラウザ側で長辺1024pxに縮小しJPEG圧縮してから送ります |
| 自動保存 | 入力中の下書きは、その端末のブラウザ（localStorage）に随時保存。誤って閉じても続きから書けます。提出すると下書きは消えます |
| 提出の演出 | 提出成功時に画面いっぱいの紙吹雪 |
| おへんじ通知 | 未読のおへんじがあると画面上部にバナー。開くとその端末で既読になります |
| カレンダー | 提出した日が色づき、おへんじ済みの日には💬マーク。日付タップでその日の記録を開けます |
| 過去の自分と対話 | ボタンを押すと**1ヶ月以上前**の自分の記録からランダムで1件表示。「今の自分から過去の自分へ」メッセージを残せます |
| おへんじの表示 | 先生のコメント・スタンプに加え、本文中のマーカー（ハイライト）もそのまま表示されます |
| ルビ（ふりがな） | 児童画面の見出し・ボタン・案内文の漢字にルビ。低学年でも一人で操作できます |

### 👩‍🏫 教員向け機能（Teacher UI）

先生の画面は**3つのタブ**で構成されます。ヘッダー右のセレクトボックスでクラスを切り替え、「クラス追加」から複数クラスを運用できます。

#### ① ジャーナル管理タブ

*   **今日の提出率**: ドーナツチャート。分母は名簿の「児童・参加中」の人数、分子は今日提出した児童数（同じ児童が複数回出しても1人と数えます）。
*   **テーマ設定**: 「今すぐ適用」で今日のテーマを設定。折りたたみの中で**月〜金の曜日別テーマ**を保存でき、当日のテーマ未設定時に自動適用されます。
*   **一覧と絞り込み**: 児童名・本文・テーマの検索、状況（未返却／返却済）の絞り込み。
*   **スタンプで即返却**: 😊👏💪⭐ のいずれかを1タップで返却。返却済みは「取消」で未返却に戻せます。
*   **詳細画面での返却**: 全体コメントに加え、**本文をドラッグ／長押しで選択するとハイライトとして登録**でき、ハイライトごとにコメントと絵文字スタンプ（8種）を付けられます。「保存して返却する」で児童に届きます。
*   **Gemini AI フィードバック支援**（APIキー設定時）:
    *   **AIシンプル**: 未返却×本文ありの全ジャーナルに、100字程度の賞賛コメント案を一括生成。
    *   **AI高度分析**: 同じ対象に、コメント案＋本文からの引用ハイライト（コメント・スタンプ付き）を一括生成。
    *   ⚠️ AIが作るのは**下書き**です。生成後もステータスは「未返却」のまま。先生が内容を確認してから返却します。
*   **一括返却**: コメントが入っている未返却ジャーナルをまとめて「返却済み」にします。

#### ② 心のバイタルタブ

*   **気にかけたい児童（自動検知）**: 次の条件に当てはまる児童を上位に表示します（Gemini は使わない、アプリ内のルールベース判定です）。
    *   直近3件のうち2件以上が「もやもや」「くやしい」→「ネガティブな感情が続いています」
    *   提出3件以上で、最新の記述量が過去平均の30%未満に急減 →「記述量が急激に減少しています」
*   **クラスの心の波（過去14日間）**: 児童 × 日付のヒートマップ。うれしい＝ローズ／なるほど＝アンバー／もやもや＝インディゴ／くやしい＝バイオレット、未提出＝グレー。丸にカーソルを合わせるとその日の本文がプレビューされます。

#### ③ クラス設定タブ

*   **児童用URLとQRコード**: URLのワンタップコピーとQR表示。参加受付のON/OFF、承認制のON/OFF、**クラスコードの再発行**（旧URLは即無効）。
*   **参加申請の承認/却下**: 名簿にないアカウントからの申請が届き、承認すると即利用開始、却下すると名簿から削除されます。タブ見出しに件数バッジが出ます。
*   **児童名簿の管理**: 役割（児童／担任）・氏名・メールアドレスを画面上で直接編集。行の追加・削除、状態（参加中／承認待ち）の表示。担任である自分は名簿から消えないよう自動で保護されます。
*   **Gemini AI 設定**: クラスのAPIキーを保存（保存済みは先頭6桁と末尾4桁のみマスク表示）。
*   **データベース**: このクラスのスプレッドシートをワンクリックで開けます。
*   **データの一括出力**: CSVダウンロード（UTF-8 BOM付き・全児童／全期間）と、印刷用帳票（児童ごとに改ページ、ブラウザの印刷ダイアログからPDF保存可）。
*   **危険な操作**: このクラスの全ジャーナル・全画像の削除（年度替わり用・確認ダイアログあり）。

## 🏗️ アーキテクチャ（3層構成 + 2デプロイ）

```
[配布層]  GitHub Pages (docs/)          … 共通URL・Googleサインイン(GIS)・PWAシェル
             │ iframe + postMessage(IDトークン + クラスコード)
             ▼
[アプリ層] GAS スタンドアロン 1 本
             ├─ デプロイ A（先生ポータル）: 実行 = アクセスユーザー
             └─ デプロイ B（児童アプリ）  : 実行 = 自分（アプリアカウント）
             │
             ▼
[データ層] クラスごとのスプレッドシート（先生所有）
           + 中央レジストリ（ScriptProperties: クラスコード → シートID）
```

### 同一プロジェクトから発行する 2 つのデプロイ（このパターンの心臓部）

|                    | デプロイ A（先生ポータル）                | デプロイ B（児童アプリ）                     |
| ------------------ | ---------------------------- | ------------------------------- |
| 次のユーザーとして実行 | **ウェブアプリケーションにアクセスしているユーザー** | **自分（アプリアカウント）**            |
| アクセスできるユーザー | 全員（または同一ドメイン）             | **全員**（＝匿名アクセス可）             |
| 本人確認手段          | `Session.getActiveUser()`      | **IDトークン検証**（`Auth.gs`）        |
| できること            | クラス作成・名簿管理・返却・AI・設定       | クラスDBへの読み書き（多段ガード + サニタイズ済み） |

*   **デプロイAが「アクセスユーザー実行」である理由**: クラス作成が先生本人の権限で走るため、`SpreadsheetApp.create()` したシートは**最初から先生のドライブに、先生所有で**できます。同じ実行内で `ss.addEditor(アプリアカウント)` を呼ぶことで共有まで自動化され、先生は共有設定を一度も開きません。
*   **デプロイBが「自分として実行」＋「全員（匿名）」である理由**: 全読み書きがアプリアカウント権限で走るので、児童にDrive上の権限を一切与えずに済みます。シートURLを知っていても開けません。さらに匿名アクセスにすることで、iframe内でログイン画面にリダイレクトされて詰む事故を回避します。
*   **クラスコードの渡し方**: シェルは児童用デプロイBを**素の exec URL** で iframe 読み込みし、クラスコードは `postMessage`（`app:idToken`）で渡します（`?t=` 付きURLの iframe 読み込みを拒否する環境があるため）。旧方式の `?t=` も受け付けます。

### クラスDB（スプレッドシート）の構成

1クラス＝1スプレッドシート（先生所有）。次の6シートが自動生成されます。

| シート | 列 |
| --- | --- |
| `児童名簿` | 役割（担任/児童）/ 氏名 / メールアドレス / 状態（active・pending） |
| `ジャーナルデータ` | journalId, timestamp, email, theme, content, imageFileId, emotion, teacherComment, highlights, teacherStamp, status（未返却/返却済み）, pastComment, deletedAt |
| `テーマ設定` | 日付 / テーマ |
| `設定` | key / value（`GEMINI_API_KEY`・`WEEKLY_THEMES`） |
| `画像データ` | imageId / chunkIndex / data / email / createdAt |
| `_meta` | key / value（schemaVersion・tenantCode・ownerEmail 等。識別用であり認可には使いません） |

## 🛠️ セットアップ手順（運営者のみが行う）

> **セットアップするのは運営者（アプリアカウントの持ち主）だけです。**
> 先生も児童も、Google Cloud や GAS の設定は一切行いません。先生は共通URLを開くだけ、児童は配られたURLを開くだけです。

### Step 0: アプリアカウントを用意

アプリ運営用の Google アカウント（例: `journal-app@gmail.com`）を用意し、**2段階認証を必ず有効化**します。
このアカウントが全クラスのシートに編集権限を持つことになります。パスワードは共有しないでください。

### Step 1: GAS プロジェクト作成

1.  **アプリアカウントで** [script.google.com](https://script.google.com) から**スタンドアロン**プロジェクトを作成します（スプレッドシートには紐付けません）。
2.  本リポジトリの `Main.gs` / `Auth.gs` / `Registry.gs` / `Tenant.gs` / `Db.gs` / `OwnerApi.gs` / `MemberApi.gs` を同名のスクリプトファイルとして、`index.html` を HTML ファイル `index` として貼り付けます（[clasp](https://github.com/google/clasp) 推奨: `clasp push`）。
3.  プロジェクトの設定（⚙️）で「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、本リポジトリの内容で置き換えます。

### Step 2: OAuth クライアント ID（GIS 用）を作成

1.  [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成 → 「APIとサービス > 認証情報」。
2.  OAuth 同意画面を構成します（外部 / アプリ名を設定）。
3.  「認証情報を作成 > OAuth クライアント ID > **ウェブアプリケーション**」
    *   承認済みの JavaScript 生成元: GitHub Pages のオリジン（例: `https://<user>.github.io`）
4.  発行されたクライアント ID を控えます。
5.  **同意画面を「本番環境に移行」します**（テストのままだとテストユーザー以外が全員拒否されます）。

### Step 3: ScriptProperties（配布元設定）

GAS エディタ「プロジェクトの設定 > スクリプト プロパティ」に登録します。

| キー | 値 |
| --- | --- |
| `sp_appAccountEmail` | アプリアカウントのメールアドレス |
| `sp_googleClientId` | Step 2 のクライアント ID（`docs/config.js` と同じ値にすること。`aud` 検証に使います） |
| `sp_shellUrl` | GitHub Pages の URL（例: `https://<user>.github.io/Reflection_Journal/`） |
| `sp_dbTemplateId` | （任意）DBテンプレートのスプレッドシート ID |

⚠️ これら `sp_*` とレジストリ（`tn_*` / `own_*`）以外を ScriptProperties に置かないでください（1値9KB / 全体500KB制限）。

### Step 4: 2 本のデプロイを発行 ⚠️ ここが最重要

「デプロイ > 新しいデプロイ > ウェブアプリ」を **2回**行います。

|  | デプロイ A（先生ポータル） | デプロイ B（児童アプリ） |
| --- | --- | --- |
| 説明 | `owner-portal` | `member-app` |
| 次のユーザーとして実行 | **ウェブアプリケーションにアクセスしているユーザー** | **自分（アプリアカウント）** |
| アクセスできるユーザー | 全員（または同一ドメイン） | **全員** |

*   デプロイBの「アクセスできるユーザー」で**「Google アカウントを持つ全員」を選ばないこと**。「全員」（匿名アクセス可）でなければ iframe 内でログイン画面に飛んで壊れます。
*   `appsscript.json` の `webapp` はデプロイA用の値です。**デプロイBは必ずデプロイ画面（UI）で設定**してください。clasp / API でデプロイを作るとBもAの設定で作られ、確実に壊れます。
*   それぞれの **exec URL** を控えます。

### Step 5: 初回承認

アプリアカウントで GAS エディタを開き、関数選択で **`authorizeApp`** を選んで「実行」→ すべて許可します。
実行ログに「UrlFetch(トークン検証): OK」と出れば完了です。
（スコープを変更した場合も、この再実行が必要です）

### Step 6: GitHub Pages（シェル）

1.  `docs/config.js` に A / B の exec URL とクライアント ID を記入して push します。
2.  リポジトリの Settings > Pages で「Deploy from a branch」/ ブランチ `main` / フォルダ `/docs` を選択します。
3.  公開 URL が `sp_shellUrl` と一致していることを確認します（**末尾スラッシュも含めて**）。

これで完了です。**先生に共通URLを伝えるだけ**で運用が始まります。
うまく動かないときは共通URLの末尾に `diag.html` を付けたページ（例: `https://<user>.github.io/Reflection_Journal/diag.html`）で接続診断ができます。

### コードを更新したとき

**GAS 側（`*.gs` / `index.html`）を変えた場合**
GAS はコードを保存しても既存デプロイは古いバージョンのまま動きます。
「デプロイ > デプロイを管理 > ✏️（編集）> バージョン: **新バージョン** > デプロイ」を **A / B 両方**に対して行ってください。
exec URL を変えないため、「新しいデプロイ」ではなく既存の編集で行うこと。
`appsscript.json` の `oauthScopes` を変更した場合は、加えて `authorizeApp()` を再実行します。

**シェル側（`docs/` 配下）を変えた場合**
`docs/sw.js` の `APP_VERSION`（`const APP_VERSION = 'v5';`）を**必ず1つ上げて**ください。上げ忘れると、既に開いたことのある端末に古いシェルがキャッシュから出続けます。
バージョンを上げると、次回アクセス時に児童の画面へ「あたらしい バージョンが あります／さいしんに する」という帯が出ます（書いている途中で勝手に切り替わらない設計です）。

## 🧑‍🏫 使い方（要約）

詳しい手順・画面の見方は **[MANUAL.md](MANUAL.md)** を参照してください。

### 先生

1.  共通URLを開く → Googleサインイン → 先生ポータルが開きます。
2.  「クラスを作成」→ クラス名を入力 → あなたのDriveにDBスプレッドシートが自動作成され、**児童用URL（QRコード付き）**が発行されます。
3.  児童用URLを児童に配ります。名簿に児童のメールアドレスを事前登録しておくと、児童は承認なしで即参加できます。名簿にない児童は「参加申請」として届くので、クラス設定タブで承認します。

### 児童

1.  先生から配られたURL（`?t=クラスコード` 付き）を開く → Googleサインイン。
2.  名簿に登録済みならそのままアプリが開きます。未登録なら名前を入力して参加申請 → 先生の承認後に使えます。

### 旧バージョンからの移行

旧バージョン（ユーザーごと個別DB方式）で使っていたDBスプレッドシートは、先生ポータルの「以前のスプレッドシートを取り込む」から、そのままクラスとして登録できます（必須シート・列は自動補完されます）。取り込むシートは、**先生本人が編集権限を持っている**必要があります。

## 🔒 セキュリティ設計

### 信頼できる入力は 2 つだけ

| デプロイ | 信用してよい情報源 |
| --- | --- |
| A（先生ポータル） | `Session.getActiveUser().getEmail()` |
| B（児童アプリ） | `verifyIdToken_()` を通過した email |

それ以外（`e.parameter`、`postMessage` の中身、`google.script.run` の引数、クラスコード）はすべて改ざん可能として扱います。**フロントから受け取った email を書き込み者として記録することはありません。**

### 多段ガード

児童向けのすべてのAPIは、処理前に必ずこの順で検証します（`guardMember_`）。

```
① トークン検証（aud / iss / exp / email_verified）
② テナント解決（レジストリ照合・revoked 拒否）
③ 名簿照合（状態 = active でなければ拒否）
④ 役割チェック（先生専用APIは所有者検証 assertOwner_）
⑤ 行所有者チェック（他人のジャーナルは更新不可）
```

フロントでボタンを隠すのは防御とみなしません。`google.script.run` を DevTools から直接叩かれる前提で設計されています。

### 情報の露出制御

*   **スプレッドシートIDは児童側に一切露出しません**（URL・APIレスポンス・HTMLのどこにも出ません。クラスコードから毎回サーバー側で解決します）。
*   児童向けレスポンスの email は匿名ID（`uid = "u" + sha256(email) の先頭12桁`）に置換されます。
*   画像は、児童は**自分がアップロードしたものだけ**取得できます（先生は担任するクラスの全画像を閲覧可）。
*   Gemini APIキーはクラスDB（先生所有シート）の設定シートに保存され、児童向けAPIからは一切返しません。先生の画面にもマスクした値しか返しません。
*   診断API（`?diag=1`）が返すのは、アプリ名・スキーマ版・デプロイ種別・匿名アクセス可否・**設定済みか（true/false）** と、`sp_shellUrl`（児童用URLに含まれる公開情報）だけです。メールアドレス・クライアントID・スプレッドシートIDなどの値は返しません。

### その他の設計判断

*   **`DriveApp` を使いません**。OAuthスコープは `spreadsheets` / `script.external_request` / `userinfo.email` の3つだけです（フルDriveスコープ回避）。画像は圧縮したData URLをシートに分割保存（40,000文字/セル）し、エクスポートはCSVダウンロード + ブラウザ印刷で実現しています。
*   **クラスコードは宛先であって認証ではありません**。8桁・32文字種（紛らわしい I,1,O,0 を除外）で約1.1兆通り。コードが漏れても、名簿にない者は承認待ち止まりです。コードの再発行・受付停止は先生ポータルからいつでも可能です（再発行後、旧URLは無効になります）。
*   **IDトークンは `sessionStorage` にのみ保持**します（共用端末対策）。失効60秒前から期限切れとみなして自動再取得します。
*   **iframe埋め込み（`ALLOWALL`）の代償**として、GAS側はシェルのオリジンからのメッセージのみ受理し、シェル側は `script.google.com` / `*.googleusercontent.com` からのメッセージのみ受理します。最終防衛線はIDトークンのサーバー側検証です。
*   児童モードの iframe は `credentialless` で読み込み、ブラウザにログイン中の別アカウントのCookieがGASへのアクセスを妨げないようにしています。
*   トークン検証・クラス情報（レジストリ）の読み取りは CacheService を前置し、UrlFetch / Properties の日次上限を回避しています。
*   CSVは数式として解釈されうる先頭文字（`= + - @` など）をクォートで無害化しています（CSVインジェクション対策）。本文をHTMLとして描画する箇所（ハイライト表示・印刷帳票）は必ずエスケープしてから組み立てます。

### 外部に出る通信（把握しておくべき点）

*   `docs/` と `index.html` は React / Babel / Tailwind / canvas-confetti / Google Fonts を **CDNから読み込みます**（オフラインでは動作しません）。
*   先生の「クラス設定」タブのQRコードは、外部サービス `api.qrserver.com` に**児童用URLを渡して**画像生成しています。組織のポリシー上これが問題になる場合は、当該 `<img>` をローカル生成に差し替えてください。
*   Gemini API へは、AI機能を実行したときにだけ**ジャーナル本文**が送信されます（先生がAPIキーを設定した場合のみ）。

### 受け入れチェックリスト（導入時に必ず確認）

- [ ] 先生Aが作ったクラスが、別の先生のポータルに**表示されない**
- [ ] 児童がシートURLを直接開くと**権限エラー**になる
- [ ] `google.script.run` を直接叩いて他人の journalId を指定しても**サーバー側で拒否**される
- [ ] シークレットウィンドウでデプロイBの exec URL を開いて**ログイン画面が出ない**（出たら設定ミス）
- [ ] クラスコード再発行後、旧コードのURLが無効になる
- [ ] 先生の同意画面に出るスコープが3つのみ

## 📉 クォータと限界

| 項目 | 上限（無料アカウント） | 対策 |
| --- | --- | --- |
| 同時実行 | 約30 | 書き込みはScriptLockで直列化。競合（`LOCK_BUSY`）時は児童側の書き込みが指数バックオフで最大3回リトライ |
| UrlFetch | 日次20,000回 | トークン検証をCacheServiceで前置（TTL 300秒） |
| ScriptProperties | 1値9KB / 全体500KB | レジストリ以外を置かない。クラス情報の読み取りはCache前置（TTL 600秒） |
| セル文字数 | 50,000 | 画像Data URLは40,000文字ずつチャンク保存。クライアント側で長辺1024pxに縮小し、700,000文字を超える画像は送信前に拒否（サーバー側上限は800,000文字） |

児童数が増えてデプロイBのアプリアカウント割り当てが限界に達したら、クラス群ごとにBを別アプリアカウントでデプロイし、シェルの `config.js` で振り分ける水平分割に拡張できます。

### 現在の実装で「できないこと」

ドキュメントとの食い違いを避けるため、よく期待されるが**未実装**の点を明記します。

*   ジャーナルの個別削除（`opDeleteJournal`）とクラスを閉じる操作（`opRevokeTenant`）は、サーバー側APIは存在しますが**画面からは呼べません**。必要な場合はスプレッドシートを直接編集してください。
*   CSVエクスポートのAPIは期間・児童での絞り込みに対応していますが、**画面のボタンは常に全期間・全児童**で出力します。
*   児童から先生へのメッセージ送信、児童同士の相互閲覧、通知メールの送信はありません。
*   下書きの自動保存・おへんじの既読はその**端末のブラウザ内**にのみ保存されます（別端末には引き継がれません）。

## 🧰 トラブルシューティング

まず共通URL＋`diag.html`（例: `https://<user>.github.io/Reflection_Journal/diag.html`）を開いてください。A/B両方が「OK」なら設置は正常です。

| 症状 | 原因と対処 |
| --- | --- |
| 診断で「デプロイ B」がNG／児童の画面がログイン画面になる | デプロイBの「アクセスできるユーザー」が「全員」（匿名可）になっていません。デプロイ画面で修正します |
| 診断で A と B の「デプロイ種別」が入れ替わっている | 「次のユーザーとして実行」の設定が逆です。A=アクセスユーザー、B=自分（アプリアカウント） |
| 「アプリの設定が未完了です」と出る | `docs/config.js` の exec URL 2本 / クライアントID のいずれかが空です |
| 「アプリの初期設定（sp_◯◯）がまだ行われていません」 | ScriptProperties の該当キーが未設定です（Step 3） |
| 児童側で「UrlFetchApp を呼び出す権限がありません」 | `authorizeApp()` の実行（Step 5）が未了、またはスコープ変更後に再実行していません |
| クラス作成時に「シートは作成できましたが、アプリへの共有に失敗しました」 | Google Workspace の外部共有制限です。管理者にアプリアカウントへの共有許可を確認してください。ドライブに残った「【作成失敗・削除してください】…」のシートは削除して構いません |
| 「データベースにアクセスできません」 | クラスのスプレッドシートが削除された、またはアプリアカウントの編集権限が外れています。共有し直してください |
| 先生の画面が真っ白／iframeが表示されない | デプロイAはログイン必須のため、ブラウザによってはiframeにCookieが渡りません。フォールバック画面の「Googleにログインして戻る（別タブ）」を使ってください |
| 「参加申請は先生の承認待ちです」から進まない | 先生が「クラス設定」タブで承認する必要があります |
| 「このクラスコードは無効です」 | コードが再発行されています。新しい児童用URLを配り直してください |
| コードを更新したのに反映されない | GAS側は A/B 両方の「デプロイを管理 > 編集 > 新バージョン」、シェル側は `docs/sw.js` の `APP_VERSION` 更新が必要です |
